# LaborTracker walkthrough

1. Open [LaborTracker](https://labortracker-cab93.web.app/) and choose **Open demo workspace**. Choose **Continue as guest** if you only want to view the sample dashboard.
2. On **Dashboard**, review open and completed deliveries, flagged handoffs, labor totals, and each crew member's shift progress.
3. Open **Deliveries**. Search or filter the active board, then select a delivery to inspect its assignment, status, notes, and activity. Use **New delivery** to enter a customer, address, scheduled date, optional crew assignment, status, and notes. Save changes from the detail page. Deliveries marked **Delivered** move to **Delivery History**.
4. Open **Delivery History** to find completed work and use **Export CSV** when you need a copy.
5. Open **Labor & Crew** to add a work-hours entry for a crew member, optionally linking it to a delivery. Filter the timesheet by date or crew member, remove an incorrect entry, or use **Export hours CSV**. Super Admin and Admin roles have full access; OperationsAdmin can add crew; Lead and RegionalAdmin have scoped labor access; the User role cannot manage staff.
6. Open **Settings** to change the company label or daily shift target. Expand **Optional** to choose whether to show Heshware Ads, allow Analytics cookies, or share performance information. Each choice is off by default and saved only after you select **Save preferences**. In demo mode, change the demo role to see its interface permissions or use **Reset demo data** to restore the fictional sample. Reset replaces demo edits and turns the optional choices off, so export anything you need first.
7. Open the top-right **ⓘ** control for session, role, access, and data-storage information. Profile contains account details. Sign out when finished. Firebase email/password registration and sign-in are available only when that provider and the site domain are enabled for the Firebase project.

Demo changes stay in the current browser. Signed-in workspaces also stay in that browser under the account's local key. See [Data and access](Data-and-Access.md) before using real operational records.
